## 01：实验时间线

**建议讲 2 至 3 分钟。**

开场句：“这不是一条收益持续上涨的曲线，而是我们逐步获得更强证据的过程。”

1. 2026-10-21：INV/DOM 历史超时后，Snapshot 自包含问题得到定位；新目录重跑的单任务四次经营与改进、反思通过验收。
2. 10-22 至 10-23：seed0 至 seed9 探索训练，34/40 次经营完成，8/10 任务有配对评分；整批验收未通过。结果为事后原生评分。
3. 10-23：seed10 至 seed19 探索训练，8 完整、1 回退、1 失败，35/40 次经营完成；整批验收未通过。
4. 10-23：基于训练证据定性审阅并选择 seed15/c1，冻结后先完成一对试跑。不按试跑利润重新调策略。
5. 10-26：续跑并完成 30/30 对、60 次执行，0 技术失败，冻结完整性验收通过。

横向间距不表示时间长短。训练结果、链路可靠性、冻结候选效果是三种不同主张，不可合并成“整个 RSI 已可靠”。Snapshot 问题及当前任务配额等工程变更改变实验身份，跨批次不能当作干净的算法 A/B。

## 02：逐轮修改图

**建议讲 4 至 5 分钟。**

任务顺序直接来自最新批次 `train.json`，不是 seed 升序：

**11 → 16 → 18 → 13 → 19 → 15 → 12 → 17 → 10 → 14**。

这里的“轮”是跨任务训练流中的一项任务，每项任务预算 k=1。各任务从固定 Base 进行任务内改进，前序任务的经验进入改进经验库；**不能解释为同一个执行 Harness 连续升级十次**。

- 文件修改通过实际 `harnesses/c1` 与该任务 `harnesses/base` 对比核对，忽略 README 占位和空的 always-on 文件。表内语义摘要也参考合成决策。
- seed15 行突出显示，因为它是最后冻结候选的来源，不是因为它排在最后或收益最大。
- seed13 是完整执行但亏损的候选；它的经营规则并未保证每次都算全资金敞口。完整不等于成功。
- seed10 基线失败，利润缺失标记为“缺失”，不能填 0。
- seed14 回退到 Base，文件差异为 0，不能算成功修改；两次 Base 执行仍可能因模型随机性产生小幅收益差。
- 表内利润差直接从每个任务最终执行与 Base 的原生结算净利润相减，不是同一评测集上的版本收益曲线。旧 `results-summary` 先将资产各自保留两位再相减，会出现 0.01 的舍入差（如 seed13）；本图以未提前舍入的原生值为准。
- 规则以整套技能为主，缺乏单规则消融，不能把一行利润变化归因于某一句提示词或某个脚本。

## 03：带区间的收益对比图

**建议讲 4 至 5 分钟。**

### 数据与统计

- 评估固定的 Base 与 seed15/c1 冻结候选（runner 将候选臂命名为 `agg`）。
- seed1000 至 seed1009，每 seed 3 次重复，2 臂，共 60 次执行、30 对。全部完成，无技术失败或失败重试。
- 每次均为全新经营 episode，无库存、工作笔记等跨 episode 传递，模型仍有采样随机性。
- 每次配置 **24 小时经营窗口**，之后继续订单交付与结算。净利润取最终原生结算值，不取 H24 观察快照。
- 初始资产 3,000（可采购现金 2,000 + 保证金 1,000）；所有收益单位为模拟货币，不是人民币、GMV 或真实现金回报。

| 统计量 | 值 | 来源 |
|---|---:|---|
| Base 平均净利润 | 469.149941 | 最终报告；本次按结果与原生测量复核 |
| 候选平均净利润 | 805.775478 | 同上 |
| 候选 − Base 配对平均增益 | 336.625537 | 同上 |
| 增益的 95% bootstrap 区间 | [226.949198, 449.224912] | 最终报告；本次复现 |
| 相对 Base 利润均值提高 | 71.752228% | 配对增益 / Base 利润均值 |
| 候选胜出 | 25/30 对 | 本次按完整配对计算 |
| seed 重复均值差为正 | 10/10 | 本次计算 |

两臂均值的区间是**本次作图新增的离线统计**，不是原报告原有字段；原报告的 `profit_stddev` 是执行收益标准差，不能直接画成 95% 均值区间。精确端点见 `evidence.json` 的 `arm_mean_95ci`。

区间算法与仓库 `paired_summary` 对齐：

1. 每 seed 先对 3 次重复取均值。
2. 用 `random.Random(0)` 按 seed 整簇重采样 2,000 次，每次抽 10 个 seed（有放回）。两个臂共享同一抽样，保留配对。
3. 将重采样均值排序，取索引 49 和 1949 作为原有实现采用的近似 2.5% / 97.5% 端点。
4. 配对差的区间与保存的最终报告逐项核对。两臂均值区间不能用来替代配对差检验，也不应按两区间是否重叠判断显著性。

主讲右侧配对差，而不是只强调百分比。95% 区间是估计方法的不确定性呈现，不表示“未来任一店铺收益有 95% 概率在此范围内”。10 个同分布新 seed 不证明分布外、长期、真实电商泛化；该实验也未单独证明经验库、递归深度或某一规则的因果收益。

## 04：最终版本流转图

**建议讲 3 至 4 分钟。**

### 任务内自动化与实验外选择的边界

- seed15 的固定 Base 分别形成通用候选 INV 和领域候选 DOM。两路探测轨迹供 COMPOSE 合成 c1，不画成 INV → DOM 的累积版本继承。
- c1 的有效内容为系统提示与 `merchant-operating-cycle` 技能，没有新增可执行 helper。
- k=1 时只有一个最终候选 c1，因此任务内选用它不需要额外 selector 模型会话。
- 之后进行一次**实验外定性审阅与选择**，记录预算、储备、已成交采购均价、发货与总交期区分等理由，选用 seed15。没有发现统一评分、权重、阈值或预注册筛选规则，也不能只凭这些记录确认每条理由由人独立形成。
- seed16 的训练利润更高；不能称 seed15 是自动挑出的最高收益或统计最优版本。
- 冻结评估不用人工纠正每次经营动作，也不在试跑或后续结果上修改候选。若调策略，应建立新身份及新确认集。

### 指纹与标准化

- 训练候选原始指纹：`2ec54d17ed3826ee`。
- 冻结候选快照指纹：`20d45ac8d63e55b6`。
- 冻结 Base 快照指纹：`471dfcf713d09935`。
- 原始目录与冻结目录字节级布局不同：标准快照省略 README 占位，并将缺失的 always-on 文件物化为空文件。已逐文件核对有效编辑内容一致；不能把指纹变化误报为策略重写，也不能称目录完全逐字节相同。
- 配对验证无 improver、selector、反思或经验库更新。
- 使用 trusted-local clean 配置隔离，不是对抗式安全盲测沙箱。

## 复算与验证

从仓库根目录运行，使用项目现有 Python 环境，不增加依赖：

```sh
.venv/bin/python docs/presentation/ecom-rsi/build_figures.py
.venv/bin/python docs/presentation/ecom-rsi/build_figures.py --check
.venv/bin/ruff check docs/presentation/ecom-rsi/build_figures.py
```

默认命令会重新生成四个 SVG、静态预览页及白名单证据 JSON，只写本素材目录。脚本核对 60 个结果与其原生测量 SHA-256 / 最终收益、两个冻结树的指纹、源候选有效文本、逐轮文件差异，以及完整报告和聚类 bootstrap。

PNG 由浏览器在 1920×1080、device scale factor 1 直接渲染独立 SVG。重新生成 SVG 后需重新导出对应 PNG；不是由 Python 生成器自动截图。新导出后执行：

```sh
.venv/bin/python docs/presentation/ecom-rsi/build_figures.py --stamp-png
.venv/bin/python docs/presentation/ecom-rsi/build_figures.py --check
```

`--stamp-png` 只给派生 PNG 写入源 SVG 的 SHA-256 元数据，不改变像素、不修改实验。仅应在确实重新导出 PNG 后执行，不能用它给旧图补签。`--check` 检查 PNG 尺寸、CRC 和 SVG 绑定，且零文件写入。
